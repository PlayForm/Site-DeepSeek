The turn

A turn is zero or more steps, and a step is one model request plus the tools it calls. One entry per stage, in the order the turn reaches it; a seam the family uses is lit, and a seam it does not use stays quiet.

  1. 01

    Queue

    Enters
    the message the user sends
    Leaves
    an inbox entry, announced live

  2. 02

    Leaves

The rail names what enters each stage and what leaves it, so the turn reads as a chain of inputs and outputs rather than a list of names.

The call

The model asks for a tool, and the harness decides 4 times: whether the call may run, what body runs, what the model reads back, and what is frozen as the record.
  1. 01

    The gate

    tools/pre-execute
    Receives
    the call the model asked for, by name and arguments
    Decides
    • allow
    • deny
    • ask
    Branch approval/request

    An ask is one prompt, and the call waits on it: allowed once continues to the guards, and rejected, cancelled, or unavailable is a deny.

    Plugin
    • hook-dsh-workspace-govern
    • plugin-dsh-batch-edit

    The model reads nothing different unless the gate refuses, and then the body never runs and the refusal becomes the result the model reads.

  2. 02

    The body

    tools/execute
    Receives
    the allowed call, wrapped for timeout, retry, and metrics
    Decides
    the docs name none here
    Plugin
    • plugin-dsh-batch-edit
    • hook-dsh-ccr

    Nothing here is rewritten: the family supplies two of the bodies that run, and a result the CCR hook stored comes back only through one of them.

  3. 03

    The result

    tools/post-execute
    Receives
    the result, before it becomes model content
    Decides
    • accept
    • block
    • replace
    • add context
    Plugin
    • hook-dsh-ccr
    • hook-dsh-comment-filter
    • hook-dsh-workspace-govern

    The model reads a one-line preview and a retrieval marker where the full result was, or a source file with its comments gone.

  4. 04

    The record

    tools/result
    Receives
    the frozen outcome, after normalization and the last content invariant
    Decides
    the docs name none here
    Plugin none of the four

    Nothing changes here: the outcome is frozen, so every change the family makes is already inside the content the model reads.

The recordtools/resultnonenone

Every change the family makes to a call happens between the gate and the result: a call can be refused before it runs, and a result can be rewritten before it is read. A hook at either seam is a waterfall listener, so it calls the harness's next() and returns the payload the next listener sees.

The fate

The call's life is one line, and every way off it is an exit, not a step. A refusal leaves before the body runs, and a failure or a timeout leaves while it runs.

  1. proposed the model asked for the call allow
  2. gated a listener allowed it dispatch
  3. running the tool body is executing return
  4. settled the result is the model's next input
  • denied a listener refused it from proposed
  • failed the body raised from running
  • background the body outlived its window from running

The conversation

One entry per part of the message the model reads, in the order it reads them, and the 4 seam that can change them.
  1. 01

    System

    The system prompt: the instructions, the step's admitted tool schemas, and every registered section, assembled fresh for each step.

    Seam
    • system-prompt/assemble
    Plugin
    • hook-dsh-live-containers
    • hook-dsh-tool-coach

    live-containers appends a live section at every assembly, and tool-coach appends a persistent coaching section once its ladder escalates.

  2. 02

    User

    The user messages: the batch the inbox delivers and the step claims, admitted as user/message before the request is frozen.

    Seam
    • agent/pre-step
    Plugin
    none

    unchanged

  3. 03

    Assistant

    The assistant messages: the text and reasoning the stream carries, settled as assistant/message and replayed as history.

    Seam
    • llm/stream
    Plugin
    • hook-dsh-normalize-dash

    normalize-dash rewrites the dash family in each delta and in the assembled block before the stream is settled.

  4. 04

    Tool

    The tool results: what the pipeline returns for each call, before the result becomes model content.

    Seam
    • tools/post-execute
    Plugin
    • hook-dsh-ccr
    • hook-dsh-tool-coach

    CCR replaces an oversized result with a preview and a retrieval marker, and tool-coach prepends a coaching note once a pattern repeats past its threshold.

The model never sees the harness, only the messages the log projects: every request has to be reconstructable from the log, so the seam that changes a message changes what the next request carries.

The composition

18 arms across 6 seam, in the order they run, and each one is registered twice, at the same seam in the same position.

agent/pre-step

5 arm
  1. 01 hook-dsh-comment-filter plain reads the intent it will act on later
  2. 02 hook-dsh-tool-coach plain adds a coaching note to the step
  3. 03 hook-dsh-live-containers plain adds the live container state
  4. 04 plugin-dsh-batch-edit plain arms its one-shot batch flag
  5. 05 hook-dsh-ccr plain runs the middle-turn archive decision when its engine is on

The first seam of every step, and the busiest: five packages read or extend the step before the model is called.

tools/pre-execute

3 arm
  1. 01 hook-dsh-workspace-govern plain allows, denies, or asks
  2. 02 hook-dsh-tool-coach plain annotates the call it sees
  3. 03 plugin-dsh-batch-edit plain turns its armed flag into a batch

The gate: a deny here stops the call before any tool body runs, which is what makes the guard a guard.

tools/execute

1 arm
  1. 01 hook-dsh-live-containers plain wraps the tool body

The only arm around the tool body itself, which is where a timeout or a metric would attach.

tools/post-execute

6 arm
  1. 01 hook-dsh-ccr prepend compresses an oversized result into a preview and a marker
  2. 02 hook-dsh-comment-filter prepend strips comments from the result
  3. 03 hook-dsh-normalize-dash prepend normalizes the result's text
  4. 04 hook-dsh-tool-coach plain reads the result and records a lesson
  5. 05 hook-dsh-live-containers plain reads the result for its monitor
  6. 06 hook-dsh-workspace-govern plain observes the result of a call it allowed

The chain that matters: the three prepended arms run outside the plain listeners, so CCR compresses the bytes the normalizers already rewrote.

system-prompt/assemble

2 arm
  1. 01 hook-dsh-tool-coach plain adds its coaching section
  2. 02 hook-dsh-live-containers plain adds its live-state section

The prompt is assembled per step, so a section added here is added to every request the step makes.

llm/stream

1 arm
  1. 01 hook-dsh-normalize-dash plain rewrites each chunk as it arrives

The last seam before the model's text becomes the transcript, and the one place a character can still change.

A prepended arm is registered outside the listeners that mount with the bundle, so its output is what the plain listeners see. Two arms do not compose at all: cost records every committed event, and the journal records every write.
