Trace

The records the run leaves, in the order the log writes them.

01 turn turn/start durable a turn opened, before any input was claimed
02 turn agent/inbox/claimed live which message this turn took
03 step step/start durable a step began, with its request controls
04 message system/message durable the system prompt the model read
05 message user/message durable the user turn as admitted
06 message request/header durable the model, the effort, and the controls of the call
07 message agent/assistant-stream live that the stream was live, and nothing after a reload
08 message assistant/message durable the text the model produced, as settled
09 tool tool/call durable the call the model asked for
10 tool tool/result durable the result the model read next
11 step step/end durable the step closed and its tool set was disposed
12 turn agent/status live the agent went idle
13 turn turn/end durable the turn closed, and the step count it took
14 session session/flush durable the log was flushed to its file

Message

The four parts of the conversation the model reads, and the seam that can change each.

  1. 01

    System

    The system prompt: the instructions, the step's admitted tool schemas, and every registered section, assembled fresh for each step.

    Seam
    • system-prompt/assemble
    Plugin
    • hook-dsh-live-containers
    • hook-dsh-tool-coach

    live-containers appends a live section at every assembly, and tool-coach appends a persistent coaching section once its ladder escalates.

  2. 02

    User

    The user messages: the batch the inbox delivers and the step claims, admitted as user/message before the request is frozen.

    Seam
    • agent/pre-step
    Plugin
    none

    unchanged

  3. 03

    Assistant

    The assistant messages: the text and reasoning the stream carries, settled as assistant/message and replayed as history.

    Seam
    • llm/stream
    Plugin
    • hook-dsh-normalize-dash

    normalize-dash rewrites the dash family in each delta and in the assembled block before the stream is settled.

  4. 04

    Tool

    The tool results: what the pipeline returns for each call, before the result becomes model content.

    Seam
    • tools/post-execute
    Plugin
    • hook-dsh-ccr
    • hook-dsh-tool-coach

    CCR replaces an oversized result with a preview and a retrieval marker, and tool-coach prepends a coaching note once a pattern repeats past its threshold.

Call

The tool pipeline a call passes, and where a decision can stop it.

  1. 01

    The gate

    tools/pre-execute
    Receives
    the call the model asked for, by name and arguments
    Decides
    • allow
    • deny
    • ask
    Branch approval/request

    An ask is one prompt, and the call waits on it: allowed once continues to the guards, and rejected, cancelled, or unavailable is a deny.

    Plugin
    • hook-dsh-workspace-govern
    • plugin-dsh-batch-edit

    The model reads nothing different unless the gate refuses, and then the body never runs and the refusal becomes the result the model reads.

  2. 02

    The body

    tools/execute
    Receives
    the allowed call, wrapped for timeout, retry, and metrics
    Decides
    the docs name none here
    Plugin
    • plugin-dsh-batch-edit
    • hook-dsh-ccr

    Nothing here is rewritten: the family supplies two of the bodies that run, and a result the CCR hook stored comes back only through one of them.

  3. 03

    The result

    tools/post-execute
    Receives
    the result, before it becomes model content
    Decides
    • accept
    • block
    • replace
    • add context
    Plugin
    • hook-dsh-ccr
    • hook-dsh-comment-filter
    • hook-dsh-workspace-govern

    The model reads a one-line preview and a retrieval marker where the full result was, or a source file with its comments gone.

  4. 04

    The record

    tools/result
    Receives
    the frozen outcome, after normalization and the last content invariant
    Decides
    the docs name none here
    Plugin none of the four

    Nothing changes here: the outcome is frozen, so every change the family makes is already inside the content the model reads.

2 of the 4 steps carry a decision vocabulary the harness documents.
