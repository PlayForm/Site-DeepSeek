Composition

How the family composes

18 arms across 6  seam, in the order they run. Order is the whole design: an arm that runs outside its neighbours sees a different payload than one that runs inside them.

Chain

Each seam is a list, not a hook. Read top to bottom: the first arm's output is the second arm's input.

agent/pre-step

5 arm
  1. 01 hook-dsh-comment-filter plain reads the intent it will act on later
  2. 02 hook-dsh-tool-coach plain adds a coaching note to the step
  3. 03 hook-dsh-live-containers plain adds the live container state
  4. 04 plugin-dsh-batch-edit plain arms its one-shot batch flag
  5. 05 hook-dsh-ccr plain runs the middle-turn archive decision when its engine is on

The first seam of every step, and the busiest: five packages read or extend the step before the model is called.

tools/pre-execute

3 arm
  1. 01 hook-dsh-workspace-govern plain allows, denies, or asks
  2. 02 hook-dsh-tool-coach plain annotates the call it sees
  3. 03 plugin-dsh-batch-edit plain turns its armed flag into a batch

The gate: a deny here stops the call before any tool body runs, which is what makes the guard a guard.

tools/execute

1 arm
  1. 01 hook-dsh-live-containers plain wraps the tool body

The only arm around the tool body itself, which is where a timeout or a metric would attach.

tools/post-execute

6 arm
  1. 01 hook-dsh-ccr prepend compresses an oversized result into a preview and a marker
  2. 02 hook-dsh-comment-filter prepend strips comments from the result
  3. 03 hook-dsh-normalize-dash prepend normalizes the result's text
  4. 04 hook-dsh-tool-coach plain reads the result and records a lesson
  5. 05 hook-dsh-live-containers plain reads the result for its monitor
  6. 06 hook-dsh-workspace-govern plain observes the result of a call it allowed

The chain that matters: the three prepended arms run outside the plain listeners, so CCR compresses the bytes the normalizers already rewrote.

system-prompt/assemble

2 arm
  1. 01 hook-dsh-tool-coach plain adds its coaching section
  2. 02 hook-dsh-live-containers plain adds its live-state section

The prompt is assembled per step, so a section added here is added to every request the step makes.

llm/stream

1 arm
  1. 01 hook-dsh-normalize-dash plain rewrites each chunk as it arrives

The last seam before the model's text becomes the transcript, and the one place a character can still change.

Position

Two positions do the work: prepend, which runs outside the plain listeners, and plain, which runs inside them.

Prepend

A prepended arm is registered outside the listeners that mount with the bundle, so it receives the payload first and its output is what the plain listeners see. The CCR gate uses this to compress the bytes the normalizers already rewrote.

Plain

A plain arm runs inside the bundle's own order. Two plain arms at one seam compose in the order the bundle lists them, which is why the profile's bundle list is part of the behavior.

Independent

Two arms do not compose at all: cost records every committed event, and the journal records every write. They run on their own seams and see nothing the chains above produce.

Tree

Classic and Effect-TS are one behavior in two trees. A composition claim holds for both, or it is not a claim about the family.

Every arm above exists twice, once as hook-dsh-* and once as ets-hook-dsh-*, with the same seam, the same position, and the same ledger string.

  • plugin-dsh-cost
  • hook-dsh-workspace-journal

The catalogue lists both trees; the turn shows the seams they stand at.

Read

The order is the order the listeners run in the family's own bundle, which is what the profile mounts. A profile that lists its bundles differently changes the plain order, and this page says so rather than presenting one profile as the only one.
