What it does

Compresses oversized tool output, caches it, and retrieves it on demand.

Read the full description in the README.

The gate on oversized tool output: whole, stored, or a marker the model can retrieve

Plugs into the tools/post-execute waterfall (prepended), the ccr_retrieve tool, and the agent/pre-step engine phase.

  • Reads the result, the tool name, and the failure flag before any other listener sees them
  • Returns pass, store, or replace, and writes the store only for the last two
  • Replaces an oversized result with a one-line type-aware preview and a retrieval marker
  • Answers ccr_retrieve by exact hash, or by a line range inside that hash

The gate reads the content, the tool name, and the failure flag, and returns one verdict; only the last two write the store, and the write happens before the verdict leaves.

  1. pass empty content, an exempt tool, a failure while compressFailures is off, a name outside targets, or a size at or under the threshold times the type's multiplier
  2. store over the gate, with auto-expand on and the size at or under its ceiling: the full content returns, the entry is retrievable, and no marker reaches the model
  3. replace over the gate and over the auto-expand ceiling: one preview line and one retrieval marker, while the original stays in the store

When Size is the UTF-8 byte length of the serialized content. The default configuration returns replace only above the auto-expand ceiling of 102400 bytes; at or under it the same result returns store, and at or under 1024 bytes times the type's multiplier it returns pass.

Flow

The order this package's work happens in, with the branch that decides it inline, transcribed from the source and from the corpus where the corpus draws it.

  1. 01
    1. seam tools/post-execute on the result
    why

    The dispatch arrives after the tool ran and before the model reads anything.

  2. 02
    branch the result is smaller than the ceiling
    why

    It returns by identity: no marker reaches the model while the content is cheap enough to keep inline.

  3. 03
    the type is classified and the bytes are serialized
    why

    One of eight types, and the size is the UTF-8 byte length of the serialized content, not the preview's.

  4. 04
    the preview line and the marker are composed
    why

    The preview names the type, the count, and the first location; the marker carries the hash, the type, and the size.

  5. 05
    the original is stored under its hash
    why

    An LRU store with a byte budget and a TTL: the oldest and the expired entries evict first.

  6. 06
    the model reads the preview, not the bytes
    why

    The result the model sees is the preview plus the marker; the original is one call away.

  7. 07
    branch ccr_retrieve is called with the hash
    why

    An exact match only: no prefix, no fuzzy. A miss returns an unknown-hash line, an expired entry a gone line.

  8. 08
    the stored bytes are returned, whole or by line range
  9. 09
    store ~/.dsh/hook-dsh-ccr.log

Rule

The marker is the address: the gate replaces the bytes only when the result is over the ceiling, and the retrieval matches the hash exactly.

Never compressed

write
The author's own file write; its content is the work, not a result to compress.
edit
The edit result is the change the author asked for, and the diff is the evidence.
raw-write
A raw write is the bytes themselves; replacing it would replace the file's content with a marker.
subagent
A subagent's brief is another agent's whole answer, and the parent reads it once.
ask_user_question
The question is a gate the user answers; a marker would ask the user to retrieve their own prompt.
ccr_retrieve
The retrieval tool's own echo; compressing it would make the restore of a restore.

Install

Default

What the harness does at this package's seam with none of the family installed, so the surface below has something to be a difference from.

The harness dispatches tools/post-execute as a waterfall and already has listeners there: claude-code-mods, hooks-claude-code, hooks-codex, repeat-tool-reminder, spill-policy, tool-fs-search.

A waterfall listener receives the payload and may return a changed one, so the harness's own listeners can already change what the model reads. This package adds another listener to that list.

Its source also registers at agent/pre-step, beyond the seam its README documents.

The family answers at this seam too: hook-dsh-ccr, hook-dsh-comment-filter, hook-dsh-convention-suggester, hook-dsh-doc-suggester, hook-dsh-edit-suggester, hook-dsh-graph-suggester, hook-dsh-replay-suggester, hook-dsh-search-suggester, hook-dsh-test-suggester, hook-dsh-tool-coach.
