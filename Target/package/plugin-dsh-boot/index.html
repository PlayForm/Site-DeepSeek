Flow

The order this package's work happens in, with the branch that decides it inline, transcribed from the source; the rule it obeys is the last band of Architecture.

  1. 01
    1. seam loader apply
    why

    The bundle's one row is applied while the harness is still on its boot rail.

  2. 02
    filter the mount list
    why

    Every specifier that is a non-empty string, in the order the config lists them.

  3. 03
    branch the list is empty
    why

    apply returns at once, and nothing is scheduled.

  4. 04
    setImmediate: hand the rail back
    why

    The loader's readiness is not held open by any import.

  5. 05
    branch the specifier already mounted in this process
    why

    Skipped, because a re-applied fiber would double-register its services.

  6. 06
    import the specifier, then mount it with an empty config
  7. 07
    record the specifier in the mounted set
    why

    In memory only: the set is what the next turn consults.

  8. 08
    fail an import or an apply throws
    why

    One warning, the specifier dropped from the set, and the rail continues.

Architecture

This plugin's own structure: the shape the portrait gives it, the facts its source documents, and the rule its flow obeys.

Shape

Plugs into the loader's apply, and the specifiers a profile lists under mount:.

The detached mount rail that keeps the family off the harness's boot path.

  • apply returns before any family plugin is imported
  • Each specifier mounted on the next turn, in config order
  • A failed import contained to one warning and one skip
  • A failed specifier retried on the next boot
Rail the loader's apply, on the harness's own boot rail
5 Parts

A plugin that awaits inside apply holds the harness's ready message open, and a stuck fiber leaves the host loading with no error anywhere, so this bundle's apply schedules the mounts and returns.

  1. 01
    the mount list read once at apply: every specifier that is a non-empty string, in the order the config lists them
  2. 02
    the detach setImmediate hands the rail back to the loader, so no import is awaited inside apply
  3. 03
    the guard a specifier this process already mounted is skipped, because a re-applied fiber would double-register its services
  4. 04
    the import a dynamic import of the specifier, then a mount with an empty config
  5. 05
    the record the specifier joins the mounted set, in memory only, so a later turn does not mount it twice
Contained

An import that throws, or a plugin whose apply rejects, is logged once as a warning, dropped from the mounted set so a later boot retries it, and never reaches the rail.

Rule

Nothing here may throw into the rail: the mount is contained per specifier, and a failure is a warning rather than a fatal.
