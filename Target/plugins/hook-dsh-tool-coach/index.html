PLUGIN DETAIL ROLE: COACH GATE: terminal tool calls (bash, pwsh)

hook-dsh-tool-coach

Hook @ DSH @ Tool @ Coach • The DeepSeek Harness Plugin Family for PlayForm. The terminal coach of the DeepSeek Harness - a plugin that teaches the model to stop using the terminal for file content. The one-sentence rule it enforces: the terminal runs COMMANDS (builds, tests, git, package managers); the tools handle CONTENT. It watches the terminal tool calls (bash, pwsh; the dedicated tools are never judged) and runs a four-tier coaching ladder that escalates from silent observation to a persistent system-prompt section to an optional hard deny.

Why it exists: terminal file edits are invisible to the plugin system - the harness's fs/observed chain (the trigger of the governor, the pinner and the normalize plugins) fires ONLY on tool-layer writes, so a sed -i/python -c edit bypasses all of them. The coach goes where that regression flows.

A NON-MANIFEST factory flavor: the family's furnace composes the schema and the volatile refresh; this package owns its schema and its strings.

The four tiers

THE COACHING LADDER

Counting in judged calls, per-agent (a WeakMap keyed on the Agent object): tier 0 logs every offense; tier 1 notes at the threshold with the cooldown; tier 2 turns on the persistent section at the escalation threshold and clears after the clean window; tier 3 denies at the enforce threshold - off by default (enforce: 'off').

From silent observation to the optional hard deny

Tier 3 is off by default (enforce: 'off'); write denies only write-class segments, all adds read and search. Discovery and control are never denied, even at all - flagging them hard would dilute the write/read signal.

Detection

DELIBERATELY ADVERSARIAL

Per pipeline (segments split on ; / && / || / &): normalize first (heredoc bodies stripped, subshells and backticks wrapped, variables marked, $IFS to space, quote layers removed, leading command word lowercased), then the pattern rows (24 built-in DEFAULT_PATTERNS; user rows appended, no built-in duplicates - fail-loud), an intent-marker scan, a craft library for the obfuscated variants, and the catch-all - any write-intent marker on a non-/dev/null path lands as write, so novel zero-day forms still count.

The pattern table is one input, not the authority

Exemptions are checked per pipeline AFTER normalization: an exempt head dominates its pipe (git diff > patch.txt is exempt), a bare echo x > tracked.md is not.

Five classes - write, read, search, discovery, control - with class-priority resolution across chained segments (cat a; sed -i ... counts once, as write).

The dynamic instruction engine

LIVE-FETCHED TOOL TABLE

ctx.tools.schemas() fetched through the same injection the model's own tools arrive by: the tool name, the FIRST SENTENCE of its description (<= 120 chars, parenthesis-aware) and the primary parameter key (parameters.properties[0]). Tier 1/3 fetch per note; tier 2 caches for sectionTtl (20) judged calls and rebuilds on tools/change. Any fetch failure degrades to the static STATIC_TOOL_LINES table and logs schema fetch failed -> static fallback; fetchLive: false is the escape hatch (static only, no failure line).

Every note names the correct tool with its LIVE registry data

Template fills are single-pass; user data is escaped before insertion, so composed output never gains an unfilled placeholder.

- read: Read a UTF-8 text file and return line-numbered content. (key parameter: file_path).

The tier-2 persistent section, placeholders filled

Tool discipline (persistent, from tool-coach):
- NEVER read file content through the terminal: "cat config.json-style" commands (cat/head/tail/sed -n/grep <file>) are forbidden — use the read and grep/glob tools.
- NEVER mutate file content through the terminal: sed -i-style commands (sed -i/awk/echo >/tee/heredoc >) are forbidden — use the write and edit tools. terminal edits produce no fs/observed event, so the governor/pinner/normalize plugins never see them.
- The terminal is for COMMANDS (builds, tests, git, package managers, process/service control).

Known limits

THE DOCUMENTED GAPS

The coach teaches; it does not rewrite. No tier modifies the model's history: tier 1 appends a note to the current turn's additionalContexts, tier 2 appends a section to the system prompt, tier 3 blocks the call before execution - the past turns are never touched.

The live fetch can fail, gracefully. A throwing ctx.tools.schemas() degrades to the static STATIC_TOOL_LINES table and logs schema fetch failed -> static fallback; the waterfall continues - a note never fails a waterfall. fetchLive: false uses the static table unconditionally with no failure line.

Detection is heuristic by design. The catch-all keeps the recall high (novel write forms still count); exemptions keep the precision acceptable (builds, tests, git, package managers, file lifecycle) - the balance is documented in the smoke battery's exempt cases, including the cat | jq carve-out dedup.
