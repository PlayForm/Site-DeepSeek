The Problem

WHY THE ELLIPSIS FLAVOR EXISTS

Text processors collapsing the typographic three-dot run into a single code point - U+2026, the horizontal ellipsis - while code blocks, commands and diffs expect three literal dots.

The collapsed typographic run is simply wrong downstream

Text processors collapse the typographic three-dot run into a single code point - U+2026, the horizontal ellipsis.

In code blocks, commands and diffs the collapsed form is simply wrong: three literal dots are what every parser, shell and search expects.

This flavor makes the ASCII spelling the one that reaches the transcript.

The scopes surface & the overpass arms

GRANULAR CONTROLALL VOLATILE

The scopes object gating every arm of the hook-dsh-normalize-ellipsis hook independently - the defaults exactly the pre-scopes behavior - with the whole object volatile: one leaf change commits one loader/volatile-update dispatch whose whole object the State's refresh listener re-reads - live, silent, no remount, no new activation line.

Every arm gated independently - and all volatile

The scopes object gates EVERY arm of the hook-dsh-normalize-ellipsis hook independently - conversation, reasoning, toolInput, toolResults, files, batch. The defaults are exactly the pre-scopes behavior.

The whole object is volatile. ONE leaf change commits one loader/volatile-update dispatch whose whole object the State's refresh listener re-reads - LIVE, silent, no remount, NO new activation line (a flip lands on the next stream).

The tool-input arm: effective tool-input normalization is normalizeToolArguments || scopes.toolInput. The field is kept and OR-ed in, so EVERY existing profile keeps working.

It is the ONLY execution-critical arm, and it carries the per-call escape hatch. A call whose arguments open with the {"__normalize":false} FIRST-key marker passes through unnormalized, the marker entry stripped (the executed call carries NO unknown key) - the "leave that search alone" control for a deliberate search for an irregular character.

The marker must be the first key: a first delta shorter than the marker is invisible to the probe and the call normalizes normally.

Three structural exemptions are NEVER rewritten: the edit call (its old_string must match the real file bytes), the raw-write call (it owns its content normalization through its explicit normalize parameter) and the normalize-file call (its arguments carry a file path - a normalized dash inside a filename would corrupt the target).

And the overpass invisibility contract: the tool-results arm replaces the bytes PRE-COMMIT - the waterfall settles before the result is appended to the durable log. The model ONLY ever sees the normalized output and NEVER notices the replacement. The exemption list plus the <<<CCR: marker guard define what passes untouched.

That is the write-path counterpart of the governance trio's never-notify precedent: the result is built from the author's own content, and the observation-policy's version record is refreshed by the re-emitted fs/observed.

The Ledger

TWO LEDGER LINESONE JOURNAL RECORD

Two ledger lines, both written through the factory's Append (the hook-dsh-normalize-ellipsis: prefix is the logger's <State.Module>:; the durable file line is [<ISO>] <message>):

hook-dsh-normalize-ellipsis: activated (replacement=..., reasoning=on, toolArgs=off, logFile=~/.dsh/playform/hook-dsh-normalize-ellipsis.log) hook-dsh-normalize-ellipsis: normalized 3 ellipsis char(s) in one stream

The activation line is written by apply(); the count line only follows a normal stream completion and only when N > 0 (a thrown-away stream writes no ledger line).

Every N > 0 pass also journals one normalized record into the shared package_governance v2 domain - event normalized, path = the empty stream-level path, detail byte-identical to the count line. The record is best-effort: with no storage facility it buffers or drops, and the human ledger stays the complete record.

One more line exists on the mount path: when the commands service refuses the normalize-overpass registration, apply() appends hook-dsh-normalize-ellipsis: command "normalize-overpass" registration skipped (the mount continues): <the registry's own message> - one line per non-first flavor per boot, and none when the registration succeeds.
