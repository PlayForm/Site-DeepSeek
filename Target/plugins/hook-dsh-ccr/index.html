PLUGIN DETAIL ROLE: COMPRESSOR GATE: tools/post-execute

hook-dsh-ccr

Hook @ DSH @ CCR • The DeepSeek Harness Plugin Family for PlayForm.

The tool-output compressor of the DeepSeek Harness - a plugin on the tools/post-execute waterfall. The waterfall is the interceptable wrapper around EVERY NORMALIZED dispatch result, before it becomes model content. The plugin replaces oversized tool output with a one-line type-aware preview plus a retrieval marker, <<<CCR:<hash>|<type>|<size>>>>. The original stays retrievable through the registered ccr_retrieve tool.

Ported from Aphrodite's CCR pipeline: compress, cache, retrieve. At the injection point a proxy cannot reach, the tool result itself.

With auto-expand on (the default), a result at or under autoExpandLimitBytes is stored but returned FULL. NO marker reaches the model while the content is cheap enough to keep inline.

A factory flavor: the family's furnace composes the schema. This package is the model logic.

How It Works

THE GATE, THE STORE, THE RETRIEVAL

The gate deciding exclusion-first: empty content passes, exempt tools pass always, failures pass unless compressFailures is on, non-target tools pass (the allow-list), anything at or under thresholdBytes x the type's multiplier passes; over the gate, auto-expand stores and returns FULL while the content is cheap enough, otherwise the result is replaced with the preview line plus the marker.

The gate order, step by step

Size = UTF-8 byte length of JSON.stringify(content). The full order the smoke asserts:

Step Condition Action
1 empty content pass (Aphrodite skips empty)
2 tool in exempt pass, always
3 failure and compressFailures off pass
4 tool not in targets pass (the allow-list)
5 size <= thresholdBytes × multiplier pass
6a over gate, autoExpand on, size <= autoExpandLimitBytes store + return FULL content (no marker)
6b over gate, otherwise replace: preview line + marker

The reduced 7-type set: error (a failure result, the x8 tier, when failures are compressed), the name table (bash -> terminal; grep/search -> grep; glob/list -> paths; read -> file; web_fetch/web_search -> web), and the shape fallback for other gated names (joined text parsing as a JSON object/array -> json; else default). Each type carries its multiplier on the byte gate.

The classifier and the multipliers

The multipliers (multipliers, volatile). Errors are high-signal and compress late (error ×8). grep/paths/web compress early (×2). The rest at parity (×1).

Type Multiplier Meaning
error 8 a failure result - high-signal, compress late
terminal 1 bash results
grep 2 grep and search results
paths 2 glob and list results
web 2 web_fetch and web_search results
file 1 read results
json 1 joined text parsing as a JSON object/array
default 1 everything else gated

The replacement content being ONE text block - [<type>:<preview>] on the first line and the <<<CCR:<24hex>|<type>|<size>>> marker on the second - every preview hard-cut to previewMaxChars (240).

The previews: pure per-type one-liners

The replacement content is ONE text block: [<type>:<preview>] plus the marker <<<CCR:<24hex>|<type>|<size>>>>. EVERY preview is hard-cut to previewMaxChars (240).

Type Preview
terminal exit <code> | <N> lines | <first significant line>
grep <N matches> matches | <first significant line>
paths <N paths> paths | <first path>
file <N lines> lines | <first significant line>
json <N items> items / <N keys> keys / <N bytes> bytes | <first line>
web <N lines> lines | <first line>
error <first significant line> (the message IS the preview)
default <N bytes> bytes | <first significant line>

An in-memory LRU keyed by the sha256-24 hash of the full serialized content bytes (node:crypto, no native deps), with the storeBudgetBytes cap (256 MiB, least-recently-accessed eviction; the just-inserted entry is never evicted), the ttlSeconds TTL (3600; sweep on insert, gone on access), and the optional JSONL disk journal (journalPath, default empty = memory-only) - one {hash, type, size, ttlAt, payload} record per store, payload base64, loaded and TTL-compacted on boot.

The store: LRU + TTL + optional JSONL journal

NOT the factory's storage journal - that is a typed lifecycle ledger, and MB-size BLOBs would corrupt the governance domain's contract. The journal is the plugin's own diagnostic file, NEVER a governed write. It is best-effort and contained (a journal failure degrades to memory-only).

One registered tool: the hash matched EXACTLY - no prefix or fuzzy matching; range {start, count} a 0-based granular line slice (out-of-range bounds clamp - a retrieval never fails for asking past the end); unknown hash a self-describing error (re-run the original tool); expired hash ditto with the TTL reason; every hit refreshes lastAccessed (the LRU clock).

The retrieval: ccr_retrieve(hash, range?)

Success value: {hash, type, size, text}. The render projects text verbatim - the model sees the original bytes, NOT an envelope.

next() always awaited FIRST (omitting it short-circuits the downstream post-execute listeners - the spill-policy precedent); pass-through returning the downstream decision unchanged; only an accepted, non-value-carrying decision replaced; the whole transform fail-open (an internal error logs a warning and keeps the inline content - never throws into the waterfall); the listener prepends so the gate sees the pristine result.

The waterfall discipline

next() is ALWAYS awaited first. Pass-through is return decision (byte-identical semantics). ONLY an accepted, non-value-carrying decision is replaced. The transform is ONE contained try/catch - fail-open, NEVER a throw into the waterfall.

The listener registers with { prepend: true }, so the gate sees the pristine result.

Known limits

THE DOCUMENTED GAPS

The context engine is implemented and OFF by default.

The phase-4 engine (contextEngine: true) adds ONE agent/pre-step listener and turns the post-execute listener into an observer. Its honest MVP does NOT remove bytes from the model's context. The pre-step decision contract covers ONLY newly claimed input messages, NOT the history. Archiving here means "stored + tracked": EVERY archived result is retrievable via ccr_retrieve through the same compress path. The decision output is ready to drive a replacement channel when one exists.

The deliberate scoping.

NO proxy mode, NO live containers (the post-execute point sees finalized results ONLY), NO poll worker, NO chain split. The system-prompt/assemble CCR-handling directive section remains unimplemented.

Failures pass through unless compressFailures is on - the error ×8 tier is the ONLY beneficiary.

The journal is best-effort.

A journal failure degrades to memory-only. The file is the plugin's own diagnostic file, NEVER a governed write.

And inlineThresholdBytes is parsed but inert under the default thresholds. It maps Aphrodite's inline_threshold and stays in the schema for the store-shape parity.
