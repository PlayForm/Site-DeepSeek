hook-dsh-live-containers

Hook @ DSH @ Live @ Containers • The DeepSeek Harness Plugin Family for PlayForm. The live-containers hook of the DeepSeek Harness - a plugin that keeps dynamic, modifiable conversation blocks in the system prompt. Each enabled block is a labeled stanza recomputed at every request - the canonical example is a time block that always holds the current time at ask-time while the rest of the conversation stays static. The blocks ride the system-prompt/assemble waterfall as ONE appended section named live-containers (interpolate: false, so only the plugin's own substitution engine touches its {{token}} groups), each block inside a fixed frame so the model cannot mistake it for harness state.

Planned - not yet in the profile. The plugin ships DISABLED (the IDLE-forever posture): the bundle entry declares enabled: false only, the plugin never appears in the profile's bundles, and it enables only by an explicit ACTIVATE. A cold mount logs disabled (enabled=false) and every listener no-ops to a passthrough.

A NON-MANIFEST factory flavor: the family's furnace composes the schema and the volatile refresh; this package owns its schema and its strings.

Known limits

THE KV-CACHE HONESTY + THE FUTURE STAGE

Per-request recompute is cache-hostile - the design says so plainly. A block whose text changes every request invalidates provider prefix reuse from its first changed token: everything after the changed byte is re-priced on the next call. refresh: "request" is therefore cache-hostile for always-differing blocks; refresh: "ttl" with ttlCalls ≥ 8 (the shipped default) is the recommended cadence - the section text holds for 8 assemblies, so the prefix stays reusable for those 8 calls - while stable-until-event blocks (notes, counters under their triggers) cost nothing extra.

The programmable stage is FUTURE - not in this package. The substitution engine is token replace ONLY - no eval, no expressions, no new Function. The later stage (research section 5) routes expression evaluation through the ptc-runtime (sandboxed, capped): kind: "program" blocks, a live_container_program tool, per-call timeout and output caps, and the privacy gate (context: 'full' per block). Do not configure for it and do not expect it from this package.

Counters are honest approximations. The plugin counts what it observes at agent/pre-step and tools/post-execute; exact token counts are NOT available to plugins, and the phase-1 counters are module-global (the assemble context exposes only an opaque scope key, which is never parsed - the family's capability rule).
