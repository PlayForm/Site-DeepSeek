PLUGIN DETAIL FLAVOR: FULLWIDTH v0.0.1 MAP FLAVOR

hook-dsh-normalize-fullwidth

Hook @ DSH @ Normalize @ Fullwidth • The DeepSeek Harness Plugin Family for PlayForm. The fullwidth normalizer for model output - a DeepSeek Harness plugin that hooks the llm/stream waterfall (the interceptable wrapper around EVERY streaming model call, bound to the LlmRuntime ) and normalizes the full-width family in model output, live in the transcript: the entire FULLWIDTH FORMS range U+FF01- U+FF5E maps to its ASCII half-width counterpart U+0021-U+007E - the whole story, letters, punctuation and digits included.

A MAP flavor of the normalize family: the core's Fullwidth char-to-char table owns the substitution - no replacement config knob.

The family's raw-write tool (registered by hook-dsh-normalize-dash ) bypasses this flavor's transforms too - the exemption is family-wide.

The Problem

WHY THE FULLWIDTH FLAVOR EXISTS

CJK input methods emitting full-width punctuation, digits and letters - a full-width comma or digit in a command, code block or path invisible on screen and wrong for every parser, shell and diff.

Full-width forms are invisible on screen and wrong everywhere else

CJK input methods emit full-width punctuation, digits and letters - and a full-width comma or digit in a command, code block or path is invisible on screen and wrong for every parser, shell and diff.

This flavor maps the whole fullwidth range to the unambiguous ASCII half-width forms before it reaches the transcript.

The scopes surface & the overpass arms

GRANULAR CONTROLALL VOLATILE

The scopes object gating every arm of the hook-dsh-normalize-fullwidth hook independently - the defaults exactly the pre-scopes behavior - with the whole object volatile: one leaf change commits one loader/volatile-update dispatch whose whole object the State's refresh listener re-reads - live, silent, no remount, no new activation line.

Every arm gated independently - and all volatile

The scopes object gates every arm of the hook-dsh-normalize-fullwidth hook independently - conversation, reasoning, toolInput, toolResults, files, batch - with the defaults exactly the pre-scopes behavior.

The whole object is volatile: one leaf change commits one loader/volatile-update dispatch whose whole object the State's refresh listener re-reads - live, silent, no remount, no new activation line (a flip lands on the next stream).

The tool-input arm: effective tool-input normalization is normalizeToolArguments || scopes.toolInput - the field is kept and OR-ed in, so every existing profile keeps working.

It is the only execution-critical arm, and it carries the per-call escape hatch: a call whose arguments open with the {"__normalize":false} FIRST-key marker passes through unnormalized, the marker entry stripped (the executed call carries no unknown key) - the "leave that search alone" control for a deliberate search for an irregular character.

The marker must be the first key: a first delta shorter than the marker is invisible to the probe and the call normalizes normally.

Three structural exemptions are never rewritten: the edit call (its old_string must match the real file bytes), the raw-write call (it owns its content normalization through its explicit normalize parameter) and the normalize-file call (its arguments carry a file path - a normalized dash inside a filename would corrupt the target).

And the overpass invisibility contract: the tool-results arm replaces the bytes PRE-COMMIT - the waterfall settles before the result is appended to the durable log - so the model only ever sees the normalized output and never notices the replacement; the exemption list plus the <<<CCR: marker guard define what passes untouched.

That is the write-path counterpart of the governance trio's never-notify precedent: the result is built from the author's own content, and the observation-policy's version record is refreshed by the re-emitted fs/observed.

In Action

ONE STREAM, ONE TRANSFORMATION

One stream, one transformation. The model emits CJK-typing artifacts - a full-width word, a full-width path punctuation run, a full-width digit; the live UI and the transcript receive the half-width ASCII forms:

Before after - the model stream, then what reaches the transcript

Every full-width code point in the incoming text - the solidus U+FF0F, the letters U+FF55-U+FF4E, the digits U+FF11-U+FF13 and the exclamation U+FF01 - becoming its U+0021-U+007E half-width counterpart, ASCII characters already half-width untouched - what keeps a pasted path openable and a pasted number parseable.

Every full-width code point becomes its half-width counterpart

Every full-width code point in the incoming text - the solidus U+FF0F, the letters U+FF55- U+FF4E, the digits U+FF11-U+FF13 and the exclamation U+FF01 - becomes its U+0021- U+007E half-width counterpart; ASCII characters that were already half-width are untouched.

This is what keeps a pasted path openable and a pasted number parseable.
