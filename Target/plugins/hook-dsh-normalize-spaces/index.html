PLUGIN DETAIL FLAVOR: SPACES v0.0.1 CLASS FLAVOR

hook-dsh-normalize-spaces

Hook @ DSH @ Normalize @ Spaces • The DeepSeek Harness Plugin Family for PlayForm. The space normalizer for model output - a DeepSeek Harness plugin that hooks the llm/stream waterfall (the interceptable wrapper around EVERY streaming model call, bound to the LlmRuntime ) and normalizes the unicode space family in model output, live in the transcript: every visible non-terminator space that is not the ASCII space becomes the plain ASCII space - U+00A0 to ' ', quads and quirs alike.

A CLASS flavor of the normalize family: the core's Spaces class plus a configurable replacement string (default " ", the plain ASCII space).

The family's raw-write tool (registered by hook-dsh-normalize-dash ) bypasses this flavor's transforms too - the exemption is family-wide.

The Problem

WHY THE SPACES FLAVOR EXISTS

Model output picking up exotic spaces - the no-break space from copy-pasted prose, the thin space from typographic text, the ideographic space from CJK input - while markdown renderers and shell quoting do not treat them as spaces, so a command with a U+00A0 in it fails for no visible reason.

Exotic spaces fail for no visible reason

Model output picks up exotic spaces - the no-break space from copy-pasted prose, the thin space from typographic text, the ideographic space from CJK input.

Markdown renderers and shell quoting do not treat them as spaces; a command with a U+00A0 in it fails for no visible reason.

This flavor makes the plain ASCII space the one that reaches the transcript.

The scopes surface & the overpass arms

GRANULAR CONTROLALL VOLATILE

The scopes object gating every arm of the hook-dsh-normalize-spaces hook independently - the defaults exactly the pre-scopes behavior - with the whole object volatile: one leaf change commits one loader/volatile-update dispatch whose whole object the State's refresh listener re-reads - live, silent, no remount, no new activation line.

Every arm gated independently - and all volatile

The scopes object gates every arm of the hook-dsh-normalize-spaces hook independently - conversation, reasoning, toolInput, toolResults, files, batch - with the defaults exactly the pre-scopes behavior.

The whole object is volatile: one leaf change commits one loader/volatile-update dispatch whose whole object the State's refresh listener re-reads - live, silent, no remount, no new activation line (a flip lands on the next stream).

The tool-input arm: effective tool-input normalization is normalizeToolArguments || scopes.toolInput - the field is kept and OR-ed in, so every existing profile keeps working.

It is the only execution-critical arm, and it carries the per-call escape hatch: a call whose arguments open with the {"__normalize":false} FIRST-key marker passes through unnormalized, the marker entry stripped (the executed call carries no unknown key) - the "leave that search alone" control for a deliberate search for an irregular character.

The marker must be the first key: a first delta shorter than the marker is invisible to the probe and the call normalizes normally.

Three structural exemptions are never rewritten: the edit call (its old_string must match the real file bytes), the raw-write call (it owns its content normalization through its explicit normalize parameter) and the normalize-file call (its arguments carry a file path - a normalized dash inside a filename would corrupt the target).

And the overpass invisibility contract: the tool-results arm replaces the bytes PRE-COMMIT - the waterfall settles before the result is appended to the durable log - so the model only ever sees the normalized output and never notices the replacement; the exemption list plus the <<<CCR: marker guard define what passes untouched.

That is the write-path counterpart of the governance trio's never-notify precedent: the result is built from the author's own content, and the observation-policy's version record is refreshed by the re-emitted fs/observed.

In Action

ONE STREAM, ONE TRANSFORMATION

One stream, one transformation.

The model emits copy-pasted typographic spacing; the live UI and the transcript receive plain ASCII spaces.

In the incoming line below the three gaps are the no-break space U+00A0, the em quad U+2003 and the ideographic space U+3000, in that order:

Before after - the model stream, then what reaches the transcript

Each non-ASCII space in the Zs-minus-ASCII class - U+00A0, U+2003, U+3000 in the sample - becoming exactly one ASCII space (U+0020), ASCII spaces already there untouched - what makes a pasted command executable again: echo a - b with a hidden no-break space running after the pass, where before the shell saw one mangled word.

Each exotic space becomes exactly one ASCII space

Each non-ASCII space in the Zs-minus-ASCII class - U+00A0 between deploy and the, U+2003 between agent and to, U+3000 between ring and buffer in the sample above - becomes exactly one ASCII space (U+0020); ASCII spaces that were already there are untouched.

This is what makes a pasted command executable again: echo a - b with a hidden no-break space between the arguments runs after the pass, where before the pass the shell saw one mangled word.
