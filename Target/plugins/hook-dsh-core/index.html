Where It Fits

FAMILY POSITION: THE BASE LIBRARY

Family position

The base library of the whole family (Hook @ DSH @ Core) - parent of NONE, child of NONE - consumed by ALL thirteen other packages.

The governance half the factory-era governance hooks (governor-package, pinner-package, governor-cargo). The normalize half the six stream normalizers (normalize-dash, quotes, ellipsis, spaces, invisible, fullwidth).

Library consumption, not bundle registration

The fs/observed + fs/write-intent seams supplying the governance half, with the three governance hooks composing their passes from the section list, the exclusion fence, the policy loader, the refusal guard and the update-stage envelope.

Governance inside consumer passes

The fs/observed + fs/write-intent seams supply the governance half the three governance hooks compose their passes from. The half is the section list, the exclusion fence, the policy loader, the refusal guard and the update-stage envelope.

Consumer-owned logging

The Problem

WHY THE CORE EXISTS

The same pure functions copy-pasted across the family's hooks: the NPM section list, the exclusion segments, the suppression-line composer, the policy loader, the refusal guard - and, for the normalize flavors, the same per-chunk dispatch, block-end normalizer and character tables.

The same pure functions, re-implemented per hook

The family's hooks kept re-implementing the same pure functions: the NPM section list, the exclusion segments, the suppression-line composer, the policy loader, the refusal guard - and, for the normalize flavors, the same per-chunk dispatch, block-end normalizer and character tables, copy-pasted per flavor.

EVERY fix had to be applied N times.

The repeated copies converging on the core's single implementations, importable by any consumer.

Each of them exists once

The core makes EACH of them exist once, importable by ANY consumer.

The same imported helpers running inside a DeepSeek Harness plugin listener and in a standalone script with no harness at all.

Inside the harness or entirely outside it

The same imports work inside the DeepSeek Harness or entirely outside it.

Normalization Helpers

TABLES, REPLACERS, AND RESULT CONTRACT

Show Dashes, Quotes, Ellipsis, Spaces, Invisible, and Fullwidth as independent flavor inputs. Distinguish character classes from character maps; do not imply that every flavor applies every table.

Six normalization tables

The normalization half supplies six character classes or maps, EACH used by its corresponding flavor.

  • Dashes - the em/en/unicode dash class
  • Quotes - eight curly-to-straight mappings
  • Ellipsis - the U+2026 class
  • Spaces - Zs characters excluding ASCII space
  • Invisible - the zero-width/format class
  • Fullwidth - 94 mappings from FF01-FF5E to 21-7E

In Action

THE HELPERS IN A CONSUMER'S CODE

A governance hook's listener catch composing the Suppress line from module, kind and cause, and sending it to its logger - never the ledger.

Suppression in a consumer's listener

EVERY contained throw in a governance hook's listener logs the same shape of line through Suppress: 

Context.logger.warn(Suppress("hook-dsh-package-governor", "listener", String(Error)));
// -> "hook-dsh-package-governor: listener error (suppressed): cannot get property ..."

The transform calling Refusal before the write: a difference outside the declared dependency sections composing the refusal line and returning null - the rewrite never applied.

The refusal guard before any write

Before ANY write, the transform runs the refusal guard - ONLY the declared dependency sections may differ: 

if (Refusal(Append, Path, Section, Document, Next)) {
	return null; // the byte-identical line went to the ledger, the write did not happen
	// -> `REFUSED rewrite of <path>: non-dependency section "scripts" would change`
}

‘first — then 10–15 total’ entering Replace with the Dashes class and the '-' replacement, returning the normalized text plus count 2.

Class replacement at work

The class replacer at work, with the real typographic characters the flavor tables match: 

Replace("first — then 10–15 total", Dashes, "-");
// -> { text: "first - then 10-15 total", count: 2 }

‘he said ‘hello’ — loudly’ entering ReplaceMap with Quotes: the two curly quotes becoming straight, the em dash passing through untouched, count 2.

Map replacement at work

The map replacer at work - the em dash is the Dashes class's job, NOT the Quotes map's: 

ReplaceMap("he said ‘hello’ — loudly", Quotes);
// -> { text: "he said 'hello' — loudly", count: 2 }
//    (the em dash is the Dashes class's job, not the Quotes map's)

count === 0 flowing back to the dispatch caller, which returns its original chunk or block object by identity - no copy, no reordering, no buffering.

Unchanged means identity

count === 0 means "unchanged": the dispatch caller keeps its original chunk or block object by identity instead of allocating anything new.
