Where It Fits

FAMILY POSITION: THE BASE LIBRARY

Hook @ DSH @ Core as the base library of the whole family - parent of none, child of none - with the factory-era governance hooks consuming the governance half and the six stream normalizers consuming the normalize half.

Family position

Family position (the @-sentence Hook @ DSH @ Core): the base library of the whole family - parent of none, child of none - consumed by all eleven other packages.

The governance half the factory-era governance hooks (governor-package, pinner-package, governor-cargo); the normalize half the six stream normalizers (normalize-dash, quotes, ellipsis, spaces, invisible, fullwidth).

Diagram placeholder - Library consumption, not bundle registration

The core as a plain library dependency: no [cordis.patch.yml]('Ours:Classic/packages/plugin-dsh-factory/cordis.patch.yml'), no loader contract, no dsh plugin add row - publishable on its own and built with the same prepublishOnly sequence as the family bundles.

Library consumption, not bundle registration

The core is not a plugin bundle: no cordis.patch.yml, no loader contract, publishable on its own - consumers link it as a plain library dependency, not as a bundle row, and there is no dsh plugin add row for it.

The DSH plugin family is the DeepSeek Harness plugin layer of the PlayForm ecosystem: TypeScript-first Source/ Target/, the deterministic @playform build, prepublishOnly-only - the same conventions as every other @playform package.

Diagram placeholder - Consumer-owned logging

Consumer-owned logging

Outcome: identical line shapes across all twelve plugins, in each plugin's own ledger.

Core Architecture

Show @playform/hook-dsh-core branching into governance helpers and normalization machinery. Connect each half to its consuming hooks. Do not depict the core as a registered plugin.

Two halves, one library

@playform/hook-dsh-core exposes named exports for two responsibilities: governance and normalization.

Consumers import the helpers directly. The core itself has no plugin loader contract.

Non-dependency refusal guard

Normalization Helpers

TABLES, REPLACERS, AND RESULT CONTRACT

Diagram placeholder - Six normalization tables

Show Dashes, Quotes, Ellipsis, Spaces, Invisible, and Fullwidth as independent flavor inputs. Distinguish character classes from character maps; do not imply that every flavor applies every table.

Six normalization tables

The normalization half supplies six character classes or maps, each used by its corresponding flavor.

  • Dashes - the Hermes dash class
  • Quotes - eight curly-to-straight mappings
  • Ellipsis - the U+2026 class
  • Spaces - Zs characters excluding ASCII space
  • Invisible - the zero-width/format class
  • Fullwidth - 94 mappings from FF01-FF5E to 21-7E

Diagram placeholder - Character-class replacement

Show text, a character class, and a replacement string entering Replace and returning text plus count. Annotate the fresh per-call gu regex and function replacer.

Character-class replacement

Replace applies a character-class replacement using a fresh per-call gu regex.

A function replacer keeps replacement-string dollar patterns from being interpreted. No shared lastIndex state is reused.

Diagram placeholder - Character-map replacement

Show source characters looking up replacement characters in a map. Annotate code-point-escaped regex keys, a fresh per-call regex, and a function replacer.

Character-map replacement

ReplaceMap applies a character-to-character map, with regex keys represented as code-point escapes.

Like Replace, it uses a fresh per-call regex and a function replacer.

Diagram placeholder - Text and replacement count

Show both replacers returning { text, count }. Show count === 0 leading the dispatch caller to return its original chunk or block object by identity.

Text and replacement count

Both replacers return { text, count }.count === 0 signals that no replacement was made.

That signal lets the dispatch caller retain its original chunk or block by identity when nothing changes.

Stream Dispatch

ELIGIBLE FIELDS AND PASSTHROUGH RULES

Show text-delta, optional reasoning-delta, optional tool-call-delta, and block-end routing through Chunk. Show other chunk types returning unchanged by identity.

Per-chunk dispatch

Chunk dispatches eligible chunk fields through an injected transform.

It handles text deltas, optionally reasoning and tool-call deltas, and block-end chunks. Other chunk types pass through by identity.

Diagram placeholder - Block-end normalization

Show TextBlock text, ReasoningBlock text and its runtime thinking string, and optional ToolCallBlock arguments. Show other blocks passing through by identity.

Block-end normalization

Block normalizes text in TextBlock and ReasoningBlock, including the latter's runtime thinking string field.

Tool-call arguments are optional and use the same tool-argument gate. Other blocks pass through by identity.

Diagram placeholder - Tool-argument eligibility

With ToolArgs enabled, show three outcomes: exempt edit/raw-write/normalize-file calls pass through by identity; raw-marked calls follow the raw path; remaining eligible calls receive normalization. Note that ToolArgs defaults to off.

Tool-argument eligibility

The fourth CoreChunk argument, ToolArgs, defaults to off.

When enabled, edit, raw-write, and normalize-file calls still pass through by identity. Raw-marked calls use a separate bypass; other eligible calls receive the transform.

Diagram placeholder - Per-call raw marker

Show the first-key __normalize:false marker being tracked per call id and passed as Raw. Show Stream/Strip removing the marker while leaving the argument content unnormalized.

Per-call raw marker

The first-key marker {"__normalize":false identifies a raw-marked call. Its state is tracked per call ID and passed through the fifth argument, Raw.

The raw path leaves the argument content unnormalized while Stream/Strip removes the marker.

Dispatch guarantees

The dispatchers use structural chunk and block shapes. Their stated contract is pure, total on strings, order-preserving, and unbuffered.

In Action

THE HELPERS IN A CONSUMER'S CODE

Diagram placeholder - Suppression in a consumer's listener

A governance hook's listener catch composing the Suppress line from module, kind and cause, and sending it to its logger - never the ledger.

Suppression in a consumer's listener

Every contained throw in a governance hook's listener logs the same shape of line through Suppress:

Context.logger.warn(Suppress("hook-dsh-governor-package", "listener", String(Error)));
// -> "hook-dsh-governor-package: listener error (suppressed): cannot get property ..."

Diagram placeholder - The refusal guard before any write

The transform calling Refusal before the write: a difference outside the declared dependency sections composing the refusal line and returning null - the rewrite never applied.

The refusal guard before any write

Before any write, the transform runs the refusal guard - only the declared dependency sections may differ:

if (Refusal(Append, Path, Section, Document, Next)) {
	return null; // the byte-identical line went to the ledger, the write did not happen
	// -> `REFUSED rewrite of <path>: non-dependency section "scripts" would change`
}

Diagram placeholder - Class replacement at work

‘first — then 10–15 total’ entering Replace with the Dashes class and the '-' replacement, returning the normalized text plus count 2.

Class replacement at work

The class replacer at work, with the real typographic characters the flavor tables match:

Replace("first — then 10–15 total", Dashes, "-");
// -> { text: "first - then 10-15 total", count: 2 }

Diagram placeholder - Map replacement at work

‘he said ‘hello’ — loudly’ entering ReplaceMap with Quotes: the two curly quotes becoming straight, the em dash passing through untouched, count 2.

Map replacement at work

The map replacer at work - the em dash is the Dashes class's job, not the Quotes map's:

ReplaceMap("he said ‘hello’ — loudly", Quotes);
// -> { text: "he said 'hello' — loudly", count: 2 }
//    (the em dash is the Dashes class's job, not the Quotes map's)

Unchanged means identity

count === 0 means "unchanged": the dispatch caller keeps its original chunk or block object by identity instead of allocating anything new.
